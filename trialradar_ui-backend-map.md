# TrialRadar: UI-to-backend handoff map (v3 wireframe → v4 spec)

**For:** A (Data), B (Bot/MCP/session), C (UI, `web/`) · **Date:** Oct 19, 2026
**Sources:** team README; `wireframe-v3.html` (built); the v4 spec from the design thread. The v4 rows reflect the agreed spec. `wireframe-v4.html` showed up partway through (20:11 CT) and was checked against it; see "v4 as built vs. spec" at the end.
**Shared contract (README):** `service.py` + `models.py` → `data/session.json` (path from `TRIALRADAR_DATA`), which the page follows on `/api/events`. Tool order: `extract_patient` → `find_trials` → `check_eligibility` → `rescore` → `draft_notes`.

**Status key:** **Exists** = the backend already provides it per the README · **New field/logic** = needs a new model field, derivation, or endpoint · **Preview** = UI only, no backend yet (shown with a "Preview" tag).
**CT.gov fields** are API v2 `protocolSection.*` paths unless marked otherwise. Anything marked *(verify)* hasn't been confirmed against the live schema.

## Open decisions for the team

1. **How to score unknowns in % match.** v3 counts unknowns against the score (`met / all rules`), so every trial looks red/orange (≤38%, 50% after answering). Options: (a) keep it, (b) `met / (met + failed)` with a separate "N to confirm" count, (c) show both. Must be the same in the UI and in any backend ranking.
2. **What makes a (!) "notable."** Every failed rule, or only hard/blocking ones? This also needs the `hard | fixable` tag on rules (#12).
3. **Who generates `short_name` and `plain_summary`** (#5, #6): curated for the 3 demo patients, or LLM-generated at `record_cache.py` time? Who reviews the wording (must say "testing," not "promises")?
4. **Distance tiers vs. backend.** Confirm Local ≤25 / Regional ≤100 / Nationwide. Does Nationwide get a real second fetch for the demo or stay Preview? Should drive time use a heuristic or wait?
5. **Demo script updates (person C).** Step 5 still says "drag the distance slider," so change it to tiers. Step 3 / the judge script still say "near miss," so change it to the (!) flag. Also add the Not-checked state and the Study evidence column to the walkthrough.
6. **Patient identifiers.** Should `extract_patient` store name/DOB/MRN at all, or only pre-masked values? Where does masking live (API vs. UI)? This affects session.json contents and the HIPAA-aligned claim.
7. **Time-saved benchmark.** Who sources the minutes-per-task constants? Until then the number stays labeled as an estimate with placeholder assumptions.
8. **Study evidence sourcing.** Where do FDA designations come from (manual curation for the demo?), and is CT.gov `referencesModule` enough for "evidence stage"?
9. **Weekly inbox scope.** Confirm it stays Preview for MVP. If it's on the roadmap, decide on the persistence model and the PHI-at-rest policy first.
10. **Model changes in `models.py`/`service.py`.** New fields proposed: patient `last_name`/`dob`/`mrn` (or masked variants), trial `short_name`, `plain_summary`, `has_results`, `enrollment`, `site_count`, `lead_sponsor`, `references`, rule `kind`, `fail_reason`, `next_action`, `patient_field`, plus questions with affected-trial lists and `unlock_hints`. Persons A and B should agree on these together, since both the API and MCP read them.

## v4 as built vs. spec (checked against `wireframe-v4.html`, 8:11 PM CT)

1. **Built and matching the map:** the Study evidence column (phase-based tier only, "Results: not linked yet" placeholder), the "Not checked yet" staged rows driven by the `window.TrialRadar.listTrials([nct])` / `.scoreTrial(nct)` hooks (person B: map `/api/events` session updates onto these), the editable biomarker chips, the Typed / Photo of report toggle in the rail, the Weekly inbox and Nationwide with **Preview** tags, "Not a medical device" in the footer, and the same placeholder `ASSUMPTION_MIN_*` time-saved constants.
2. **Not yet matching the spec** (the file may still be in progress): the distance control is still **25 / 50 / 100 mi + a Nationwide toggle** instead of Local ≤25 / Regional ≤100 / Nationwide. The footer and question card still say **"treating doctor" / "Questions for the doctor"** instead of "treating clinician." **"HIPAA-aligned"** wording is missing. There's no **"What would unlock more trials"** line and no **gold** next-step pill. The one-liners are still the v3 descriptive versions, not solution-oriented. No drive time yet. The weekly inbox copy says "Email me new matches," which implies sending, so consider "Show new matches in my inbox" given the README's "nothing is sent" stance.
